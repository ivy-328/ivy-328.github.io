Website Maintenance

网站内容更新说明

本个人网站基于 Jekyll + GitHub Pages 搭建，初始建站方法参考 Jay Rob Williams 的 Building an Academic Website 教程， 并在此基础上根据个人展示需求进行了进一步的页面设计与内容结构调整。

本地修改内容 → Git 记录版本 → Push 到 GitHub → GitHub Pages 自动重新发布

1. 网站内容主要存放在哪里

为方便后续维护，网站中的个人内容与页面样式尽量分开存放。 日常更新时通常只需要修改 _data 文件夹中的数据文件和 images 文件夹中的图片。

_data/profile.yml

姓名、学校、专业、研究方向、邮箱、个人简介和首页照片等。

_data/research.yml

研究项目、研究状态、时间、摘要、方法和相关信息。

_data/portfolio_v11.yml

Work 页面中的新闻、评论、视觉作品、封面和原文链接。

_data/experience.yml

实践、实习、项目经历、图片和相关链接。

_data/honors.yml

荣誉、比赛获奖及相关说明。

images/

个人照片、作品封面、实践照片及其他图片素材。

2. 哪些文件一般不需要日常修改

以下目录主要负责页面结构、组件和视觉样式：

  • _pages/：页面内容与页面入口
  • _includes/：可重复使用的页面组件
  • _layouts/：页面整体布局
  • _sass/、assets/：样式与前端资源
日常新增研究、作品、经历或荣誉时，优先修改数据文件； 只有需要改变页面布局、导航或视觉效果时，才修改这些结构文件。

3. 一次完整的网站更新流程

完成内容修改后，在 Git Bash 中进入本地网站仓库：

cd /d/git_projects/ivy-328.github.io

检查发生了哪些变化：

git status

确认修改后，将本次变化加入 Git：

git add -A

创建一个版本记录：

git commit -m "Update website content"

最后上传到 GitHub：

git push origin master

Push 成功后，GitHub Pages 会自动重新构建并发布网站。 一般不需要手动生成或上传 HTML 文件。

4. 一个简单的更新例子

例如，要在 Research 页面增加一个新的研究项目，可以打开 _data/research.yml，参考已有项目的格式增加一组数据： 

- id: example-project
  featured: true
  title_en: Example Research Project
  title_zh: 示例研究项目
  status_en: Research in Progress
  status_zh: 研究进行中
  period: 2026–
  summary_en: Brief introduction to the research project.
  summary_zh: 此处填写研究项目的中文简介。
  methods:
    - Content Analysis
    - Survey

保存后执行 Git 提交和 Push，页面模板会自动读取新的数据。 更新 Work、Practice 和 Honors 时也采用相同思路。

5. 图片如何更新

新图片先放入 images/ 下对应的位置，再在相关数据文件中填写路径，例如： 

image: /images/work/example.jpg

图片上传前应适当压缩，并尽量使用简洁的英文文件名，以减少路径错误并提高网页加载速度。

6. 发布检查与版本恢复

Push 后，可以在 GitHub 仓库的 Actions 页面查看 GitHub Pages 是否部署成功。 如果部署成功但浏览器仍显示旧页面，可以使用 Ctrl + F5 强制刷新。

网站的 Git 历史也可以用于查看以前的版本：

git log --oneline

如需撤销某一次错误更新，可优先采用：

git revert <commit-id>
git push origin master

7. 建站方法说明

本网站的初始搭建方式参考 Jay Rob Williams, “Building an Academic Website” 。

在原有 Jekyll + GitHub Pages 工作流基础上，网站进一步进行了个性化页面设计， 并将主要个人内容拆分为独立的数据文件，以降低日常更新对 HTML/CSS 页面结构的依赖。
